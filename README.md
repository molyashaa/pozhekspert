# ПожЭксперт+ — веб-приложение (учебный прототип)

Информационная система управления проектированием систем пожарной безопасности
с ИИ-помощником для ООО «ПожЭксперт+». Реализована по техническому заданию
курсового проекта: 7 ролей, проекты → этапы → задачи, версии документов,
поэтапная проверка с замечаниями, зависимости этапов, уведомления, журнал аудита,
справочник клиентов, отчёты, тёмная тема и ИИ-поиск похожих замечаний (TF-IDF).

**Стек (п. 8.1 ТЗ):** Python 3.12 · Django 5.2 · MySQL / MariaDB (XAMPP, phpMyAdmin) ·
шаблоны Django + собственный CSS по макетам · JavaScript без внешних библиотек ·
scikit-learn. Все записи демо-данных помечены как тестовые и вымышлены.

## 1. Быстрый запуск на Windows с XAMPP (для защиты)

Нужно: **Python 3.12** (при установке отметить «Add python.exe to PATH») и **XAMPP**.

1. Откройте XAMPP Control Panel → у **MySQL** нажмите **Start**
   (Apache для этого проекта не нужен).
2. Распакуйте архив проекта, например в `C:\pozhexpert`.
3. Дважды щёлкните **`setup_windows.bat`**. Скрипт сам:
   создаст виртуальное окружение → установит библиотеки → создаст `.env` →
   создаст базу `pozh_db` (utf8mb4) → создаст таблицы (миграции) → загрузит демо-данные.
4. Дважды щёлкните **`start_windows.bat`** — откроется http://127.0.0.1:8000/

Те же шаги вручную (командная строка в папке проекта):

```bat
py -3.12 -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
python manage.py create_mysql_db
python manage.py makemigrations core
python manage.py migrate
python manage.py seed_demo
python manage.py runserver
```

Проверка в phpMyAdmin: http://localhost/phpmyadmin → база `pozh_db` → таблицы
`roles`, `users`, `clients`, `projects`, `stages`, `tasks`, `documents`,
`document_versions`, `remarks`, `ai_archive` и др.

### Если что-то пошло не так

| Сообщение | Решение |
|---|---|
| `Не удалось подключиться к MySQL` | В XAMPP не запущен MySQL, или в `.env` неверные `DB_USER`/`DB_PASSWORD` (в XAMPP по умолчанию `root` без пароля) |
| Ошибка при `pip install mysqlclient` | Ничего страшного: `pip install "Django>=5.2,<5.3" PyMySQL scikit-learn whitenoise` — система сама использует PyMySQL |
| `MariaDB 10.5 or later is required` | Не возникнет: проект содержит совместимый драйвер `pozh_project/mysql_backend` для MariaDB 10.4 из XAMPP |
| Нет MySQL совсем | В `.env` поставьте `DB_ENGINE=sqlite` — база будет в файле `db.sqlite3` (запасной вариант для показа) |
| Порт 8000 занят | `python manage.py runserver 8080` |

## 3. Как это устроено (для пояснительной записки и защиты)

**Архитектура MVT Django.** Браузер → `urls.py` → функция-представление в `core/views/`
→ проверка прав (`permissions.py`) → бизнес-правило (`services.py`) → модель (`models.py`)
→ MySQL. Ответ собирается из шаблона `templates/` со стилями `static/css/app.css`.

**Права проверяются на сервере, а не только скрытием кнопок.** Каждое представление
вызывает `require(...)` / `get_project_or_403(...)`. Подмена адреса (например,
`/projects/5/` чужого проекта) даёт страницу 403. Списки (проекты, документы, замечания,
поиск, ИИ) строятся только из разрешённых записей.

**Статусы и переходы этапа:** Не начат → (запуск проекта) → В работе / Заблокирован →
Передан на проверку = «Ожидает проверки» → «Принят» или «На доработке» → … После каждого
решения `recompute_project()` пересчитывает зависимости: этап открывается, только когда все
этапы, от которых он зависит, приняты; при отмене приёмки зависимые этапы блокируются.
Циклические зависимости запрещены (поиск в графе, `check_dependencies`).

**Проверка результата:** исполнитель загружает версию → «Передать на проверку» фиксирует
версию (`submitted`) → эксперт «Принять результат» (версия `accepted`, этап «Принят») или
«Вернуть на доработку» (обязательное замечание: текст, раздел, критичность, версия).
Принять собственный результат нельзя даже прямым POST-запросом (`_check_reviewer`).

**Версии документов не перезаписываются:** каждая загрузка — новая строка
`document_versions` с номером, автором, датой, комментарием и статусом проверки.
Файлы проверяются по расширению, сигнатуре и размеру (25 МБ), сохраняются под
случайным именем, а скачиваются только через `/files/<id>/` с проверкой прав.

**ИИ-помощник** (`core/ai.py`) — не нейросеть и не внешний сервис: текст нормализуется
(нижний регистр, стоп-слова, простой русский стеммер), строится TF-IDF по словам и
символьным n-граммам, считается косинусное сходство; выдаются до 5 записей выше порога
`AI_THRESHOLD` (15 %), с объяснением «общие слова». Нет совпадений — честное сообщение.
Если scikit-learn не установлен, работает резервный алгоритм (коэффициент Жаккара).

**Журнал аудита** (`audit_log`) пишет смену статусов, назначений, сроков, ролей,
версий и записей архива ИИ: кто, когда, что было и что стало.

## 4. База данных

Основные таблицы соответствуют ER-модели: `roles`, `users`, `clients`, `projects`,
`stages`, `tasks`, `documents`, `remarks`, `ai_archive`; дополнительные по п. 9 ТЗ:
`stage_dependencies`, `assignments`, `document_versions`, `reviews`, `review_versions`,
`remark_status_history`, `remark_comments`, `notifications`, `audit_log`,
`approval_packages`, `ai_feedback`. Первичные ключи — INT AUTO_INCREMENT, связи — внешние
ключи, кодировка utf8mb4. Пароли хранятся только в виде хеша PBKDF2-SHA256.

Получить SQL-описание таблиц для пояснительной записки:
`python manage.py sqlmigrate core 0001 > schema.sql`.

## 5. Резервное копирование и восстановление (п. 8.3 ТЗ)

Копия = **дамп базы + папка `media/`** (база ссылается на файлы).

```bat
REM копия (XAMPP)
C:\xampp\mysql\bin\mysqldump -u root --default-character-set=utf8mb4 pozh_db > backup\pozh_db.sql
xcopy media backup\media /E /I /Y

REM восстановление
C:\xampp\mysql\bin\mysql -u root -e "CREATE DATABASE IF NOT EXISTS pozh_db CHARACTER SET utf8mb4"
C:\xampp\mysql\bin\mysql -u root pozh_db < backup\pozh_db.sql
xcopy backup\media media /E /I /Y
```

Тот же дамп через phpMyAdmin: база `pozh_db` → «Экспорт» → SQL. Этот файл и есть
«SQL-дамп демонстрационной базы» для переноса на другой компьютер: на новом месте
достаточно импортировать его, скопировать `media/` и запустить `runserver`
(миграции и `seed_demo` уже не нужны). После восстановления откройте карточку проекта
и скачайте документ — так проверяется тест-кейс № 19.

## 6. Размещение на хостинге

Подробная инструкция — в файле **DEPLOY.md**. Коротко: на хостинге в `.env` ставятся
`DJANGO_DEBUG=0`, длинный `DJANGO_SECRET_KEY`, домен в `DJANGO_ALLOWED_HOSTS` и
`DJANGO_CSRF_TRUSTED_ORIGINS`, реквизиты MySQL хостинга; затем
`pip install -r requirements.txt`, `makemigrations core`, `migrate`, `seed_demo`,
`collectstatic`. Статика раздаётся через whitenoise, файлы документов — через Django
с проверкой прав.

## 8. Ограничения прототипа

ИИ-помощник даёт справочные подсказки по демонстрационному архиву и не заменяет эксперта.
DWG/DXF хранятся и скачиваются, просмотр — во внешней CAD-программе. Восстановление пароля
выполняет директор («Сбросить доступ»). Автоматическое согласование с МЧС, полноценные сметы
и обучение ML-модели — перспективные функции.
